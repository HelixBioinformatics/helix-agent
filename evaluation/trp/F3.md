## Repetir las comprobaciones

Desde la raíz del repositorio:

```bash
bun script/tesis/check_trp_catalog.ts
bun script/tesis/check_trp_graph.ts
```

Desde `packages/helix`:

```bash
bun test test/trp test/tool/registry.test.ts test/nfcore test/bio
bun run typecheck
```

La prueba externa requiere Nextflow **25.10.4**, Docker y la imagen exacta del catálogo ya presente. Utiliza directorios temporales nuevos y no necesita una llamada al proveedor de lenguaje:

```bash
TRP_LIVE_REFERENCE=1 TRP_REFERENCE_OUTPUT=/tmp/trp-reference-new bun test test/trp/reference.live.test.ts
```

`TRP_REFERENCE_OUTPUT` debe ser nuevo. El controlador envía una respuesta sintética por `Question.Service.reply`; el archivo `engineering-reference.json` declara este hecho. El recorrido real pasa por `trp_prepare` y `trp_run`. La configuración se resuelve y dos tareas simuladas terminan antes de las dos tareas reales. La marca de la simulación nunca se acepta como CSV científico. Las pruebas negativas comprueban que un fallo de imagen, configuración, simulación o marca de salida bloquea el análisis.

Los manifiestos actuales son evidencia de desarrollo. La verificación portable integral de ejecuciones, el inventario y los límites presupuestarios se completan en F4. Las trazas conservan tiempos locales tal como los emitió Nextflow; no son una campaña de rendimiento.

## STRPsearch: avance con límites explícitos

Se reconstruyó el código upstream `ed325a7f6b77578ee96753f31dbdcfda4931cca8` en una imagen aislada. El Dockerfile de sondeo corrige el nombre del entorno; los paquetes resueltos, sus URL y la imagen quedan registrados. La receta usa resolución de dependencias y una imagen base móvil: **todavía no es una receta congelada para admisión**.

En ese entorno, Python carecía de una asociación MIME para `.cif`. La CLI terminó sin analizar el archivo y con código cero. Se proporcionó `/etc/mime.types` con `chemical/x-cif cif` y `chemical/x-pdb pdb ent` sin modificar el algoritmo.

Con el mmCIF completo de RCSB y red deshabilitada, Foldseek encontró dos entradas de la misma proteína; ambas fallaron en el suavizado por valores no finitos. La CLI también terminó con código cero. Se observaron fragmentos que solo contenían agua. Una copia de diagnóstico con `gemmi.Structure.remove_ligands_and_waters()` permitió completar el programa: una región 162–269, siete unidades, `reviewed=false`. Los límites difieren del ejemplo suministrado a GeomeTRe; no se sustituyen silenciosamente.

Todo el recorrido, incluida la transformación, está en [el registro de sondeo](reference/strpsearch-probe-f3/probe.json). Se conservan resultados fallidos, resultados candidatos, entradas y hashes. No es evidencia independiente de sensibilidad: 2xqh está en la propia base de búsqueda. STRPsearch sigue candidato hasta fijar la reconstrucción, verificar su contrato y hacer que errores científicos impidan declarar éxito. ReUPred y el marco de la API RepeatsDB siguen pendientes; no se declara cerrada la cobertura completa de R1.1.
