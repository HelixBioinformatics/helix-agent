# Operational continuation and separate extension

The original forty-case freeze, input hashes, unknown labels and first attempts remain immutable. The original driver stops new dispatch at its checkpoint, and each guest supervisor has its own bounded service and owned-job cleanup. A lost transport response never triggers a second submission.

After the actual driver terminates, record its terminal result in `driver-terminal.json`; run `check_r24_checkpoint.py` against the original campaign. The read-only check inspects every original Slurm comment, dispatched controller service and supervisor PID, and active containers on both exclusive campaign workers. Only a verified clean checkpoint permits stopping and starting the same instances.

`finalize_r24_checkpoint.py` can register unstarted original IDs and preserve an original supervisor refusal as unknown. It copies the producer progress before editing orchestration metadata, changes no conclusive label, and links the independent cleanup observation. A stopped supervisor without an oracle is never labeled infeasible.

The root-owned restoration helper attaches the existing XFS backing image and remounts NFS. It must never format or reset quotas. The operator refreshes private SSH configuration and verifies the minimum of Academy expiration and all three180minute boot guards. `prepare_r24_continuation.ts` freezes a renewed target and operational namespace before another dispatch. It keeps the exact scientific inputs, gold CSV and budgets; only target binding and unique job comments change. Resource demand is counted again by the unchanged production admisor and both values are retained.

Continuation uses a new quota project range beginning at20000 and a new workspace namespace, controller unit prefix, result directory and Slurm comment. It selects only unresolved original IDs after all earlier dispatched attempts have been recovered or conclusively observed stopped. This is an intentional operational amendment after a legitimate restart, never a retry inferred from an SSH timeout.

Example invocation after verified restoration and renewed configuration:

```sh
UV_NO_PROGRESS=1 uv run --with boto3 python evaluation/trp/campaign-20261012/trace/drive_r24_continuation.py --original evaluation/trp/campaign-20261012/cloud/lab2/r24-campaign --output evaluation/trp/campaign-20261012/cloud/lab2/r24-continuation --deadline 2026-10-13T03:58:00Z --namespace r24-continuation-1 --run
```

The deadline is an example, subject to the actually verified renewed window. `summarize_r24_all_attempts.py` independently checks both revisions and keeps the original40IDs as its denominator, preserving unknown attempts.

If the original grid yields fewer than20empirically infeasible cases, `prepare_r24_extension.ts` freezes a separate extension only after all original40cases are conclusively audited. The number equals the observed infeasible-group shortfall. It selects the first unused graph variants from the original frozen corpus and a64KiBhead-workspace quota, with all new labels unknown before execution. These decisions are explicitly made after observing the original grid. The original40matrix remains separate, and the extension denominator is stated. The causal transfer/quota error must still be observed; a small budget is not itself a physical label.

Both revisions and the extension remain development experiments on one protein. XFS allocated head-workspace blocks, staged inputs, work/logs and portable duplication are bounded; real local-client preparation and export are outside this oracle. Therefore scoped false rejections can diagnose conservatism for the adapted workspace but cannot be interpreted as a protocol false-rejection rate against an identical aggregate consumption scope. No scientific R2.4 or aggregate R2.2 completion follows from these runs.
